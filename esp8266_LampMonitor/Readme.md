# ESP8266 Lamp Monitor

Прошивка для ESP8266 (D1 mini) с OLED-дисплеем SSD1306. Устройство подписывается на MQTT-топик `home/lamp/status` и отображает состояние лампы на экране. Настройка Wi-Fi и MQTT — через веб-интерфейс в режиме точки доступа.

## Описание

Устройство работает как read-only подписчик MQTT: никаких публикаций в брокер, никаких команд — только приём значения из одного топика и отображение его на OLED. При потере связи с брокером дисплей явно показывает это. Настройка Wi-Fi и MQTT — через веб-интерфейс, доступный либо в режиме точки доступа при первом запуске, либо в клиентском режиме по IP, полученному от роутера.

## Возможности

- **Wi-Fi:** сканирование сетей, подключение, сохранение нескольких SSID/паролей, автоподключение при старте.
- **Режим AP:** если сохранённых сетей нет или автоподключение не удалось — устройство поднимает точку доступа `ESP32-Setup` для настройки.
- **AP-fallback:** AP не пропадает во время попытки подключения (используется `WIFI_AP_STA`); при потере Wi-Fi в клиентском режиме > 60 секунд — авто-перезагрузка с возвратом в AP.
- **MQTT (только чтение):** подписка на state-топик, приём retained-значения сразу после подключения, дедупликация одинаковых сообщений.
- **OLED:** отображение состояния Wi-Fi, MQTT и лампы (`ON` / `OFF` / `?` / `--`).
- **Веб-интерфейс:** настройка Wi-Fi и MQTT (сервер, порт, логин, пароль, state-топик).

### Слои

- **Менеджеры** (`WiFiManager`, `MqttManager`) — низкоуровневая работа с железом и библиотеками.
- **Хранилища** (`WiFiCredentials`, `MqttCredentials`) — персистентность через `Preferences` в JSON.
- **Сервисы** (`WiFiService`, `MqttService`, `LampStateService`) — фасады, связывают менеджеры с хранилищами и добавляют поведение.
- **Ядро** (`AppState`, `StateManager`, `StatusBuilder`) — композиция, состояние, сборка статуса.
- **Периферия** (`DisplayService`, `WebService`) — OLED и HTTP.

### Ключевые принципы

- **AppState** — композиционный корень. Владеет всеми сервисами, роутит MQTT-сообщения и предоставляет API для `WebService` и `DisplayService`.
- **LampStateService** — единственный потребитель MQTT-сообщений. Хранит последнее значение топика и уведомляет дисплей через колбэк.
- **Устройство read-only.** Никаких публикаций в брокер, никакой синхронизации retained-состояния обратно. Что пришло — то и показываем.

## Как это работает

### Запуск (setup)

1. Если state-топик не сохранён — устанавливается `home/lamp/status` по умолчанию.
2. Проверяется наличие сохранённых Wi-Fi-сетей:
   - **нет** → сразу AP-режим (`WebService::begin(true)`);
   - **есть** → `AppState::begin()` запускает автоподключение, ждём до 10 секунд. Успех → клиентский режим, неудача → AP.
3. `AppState::beginMqtt()` — попытка подключения к брокеру с сохранёнными настройками.

### Цикл (loop)

- `AppState::update()` — обновляет MQTT-клиент и дисплей.
- `WebService::handleClient()` — обработка HTTP-запросов и контроль потери Wi-Fi.

### MQTT-логика

**Входящие сообщения:**

```text
MqttManager → MqttService::handleMessage → AppState::handleMqttMessage
           → LampStateService::handleMqttMessage
```

`LampStateService` проверяет, что топик совпадает с нашим `stateTopic`, дедуплицирует одинаковые последовательные payload'ы и уведомляет `DisplayService` через колбэк для мгновенной перерисовки.

**Синхронизация при (пере)подключении:**

1. `MqttManager::reconnect()` после успешного connect вызывает `_onConnected`.
2. `MqttService` пробрасывает событие наружу через свой `_connectedCallback`.
3. `LampStateService::onMqttConnected()` подписывается на state-топик и сбрасывает флаг «данные есть».
4. Брокер отдаёт retained-значение → оно применяется и отображается.
5. Если retained не пришёл (пустой топик, первый запуск) — дисплей показывает `LAMP: ?` до первого сообщения.

### AP-fallback

- **В AP-режиме при попытке подключения:** используется `WIFI_AP_STA`, AP остаётся активным — веб-интерфейс доступен всё время попытки.
- **В клиентском режиме при потере Wi-Fi > 60 секунд:** `ESP.restart()`. После перезагрузки `setup()` либо подключится к сохранённой сети, либо уйдёт в AP.

## Веб-интерфейс: маршруты

| Метод | Путь      | Назначение |
|-------|-----------|------------|
| GET   | `/`       | HTML-страница (AP или клиент — в зависимости от режима) |
| GET   | `/scan`   | Сканирование Wi-Fi, возвращает JSON-массив сетей |
| POST  | `/connect`| Подключение к сети (`{ssid, password}`) |
| GET   | `/saved`  | Список сохранённых SSID |
| POST  | `/delete` | Удаление сохранённой сети (`{index}`) |
| GET   | `/status` | JSON-статус (Wi-Fi, IP, RSSI, MQTT, лампа, состояние) |
| GET   | `/mqtt`   | Текущие MQTT-настройки |
| POST  | `/mqtt`   | Сохранение MQTT-настроек, переподключение |
| POST  | `/reset`  | Удаление всех Wi-Fi и MQTT настроек, перезагрузка |
| POST  | `/reboot` | Перезагрузка устройства |

## Формат JSON-статуса (`/status`)

```json
{
  "connected": true,
  "ssid": "MyWiFi",
  "ip": "192.168.0.42",
  "rssi": -58,
  "lamp": "ON",
  "mqtt": true,
  "state": "CONNECTED"
}
```

- `lamp` — последнее значение из топика (`ON` / `OFF` / произвольная строка), либо пустая строка, если данных ещё не было.

## Известные ограничения

- **WPA3 / PMF / Wi-Fi 6 не поддерживаются** — ограничение железа ESP8266. Роутер должен раздавать WPA2-PSK (AES) с PMF в режиме Disabled или Optional.
- **Реконнект MQTT прекращается после 10 попыток** до перезагрузки устройства.
- **Нет LWT/availability-топика** — внешние системы (Home Assistant и т.п.) не узнают, что устройство отвалилось.
- **Нет аутентификации веб-интерфейса** — любой в локальной сети может управлять устройством и менять MQTT-настройки.
- **Пароль MQTT хранится в открытом виде** в `Preferences` и отдаётся в `GET /mqtt`.
- **Пароль AP захардкожен** (`12345678`).
- **Нет OTA-обновления.**
- **Дубли сообщений от брокера** — устройство защищено дедупликацией в `LampStateService`, но источник дублей должен разбираться на стороне брокера.
- **JSON в `/scan`, `/saved`, `/mqtt` собирается конкатенацией строк** — SSID со спецсимволами может сломать ответ (в `/status` используется `ArduinoJson`).
