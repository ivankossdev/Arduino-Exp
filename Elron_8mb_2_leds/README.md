# Elron ACE-NANO/UNO — Multi-timer Blink with EEPROM Settings

Учебно-демонстрационный проект для российской платы **ELBEAR ACE-UNO**
(и совместимых с ней по распиновке ACE-NANO) на микроконтроллере
**MIK32 Амур** (RISC-V, 32 МГц).

Устройство управляет двумя светодиодами, реагирует на короткое,
длинное и сверхдлинное нажатие кнопки, хранит настройки в EEPROM,
имеет интерактивную консоль по UART и heartbeat-мониторинг.

---

## Архитектура

Проект разбит на слои. Каждый модуль отвечает за одну задачу
и не знает о деталях остальных.

| Файл                    | Ответственность                                             |
|-------------------------|-------------------------------------------------------------|
| `Elron_8mb_2_leds.ino`  | Точка входа: только `appSetup()` и `appLoop()`               |
| `App.h/.cpp`            | Прикладная логика: объекты, колбэки, режимы, `applySettings` |
| `EventTimer.h/.cpp`     | Универсальный таймер на `millis()`                          |
| `Settings.h/.cpp`       | Профиль настроек, EEPROM, версии, валидация, dirty-флаг     |
| `Button.h/.cpp`         | Кнопка: антидребезг, short/long/very-long press              |
| `Console.h`             | Класс `Console` (публичный интерфейс)                        |
| `ConsoleImpl.h`         | Вспомогательные утилиты парсинга (`inline` в namespace)     |
| `Console.cpp`           | Ядро команд (`help`, `show`, `set`, `mode`, ...)             |
| `ConsoleEeprom.cpp`     | Отладка EEPROM (`dump`, `peek`, `poke`)                     |
| `ConsoleApp.cpp`        | Прикладные команды (`stats`, `clearstats`, `led2`)           |

### Идея слоёв

```text
┌──────────────────────────────────────────┐
│ .ino │ ← glue из 8 строк
├──────────────────────────────────────────┤
│ App │ ← прикладная логика
├──────────────────────────────────────────┤
│ EventTimer │ Settings │ Button │ Console │ ← переиспользуемые модули
├──────────────────────────────────────────┤
│ Arduino core (MIK32 Амур BSP) │
└──────────────────────────────────────────┘
```

`EventTimer`, `Settings`, `Button`, `Console` **не знают друг о друге**.
Вся координация — в `App.cpp` через колбэки.

## Что делает устройство

- **LED1** (`LED_BUILTIN`, пин D22) мигает по одному из трёх режимов:
  - `SLOW` — период из `settings.intervalSlow` (по умолчанию 1000 мс)
  - `FAST` — период из `settings.intervalFast` (по умолчанию 250 мс)
  - `OFF`  — LED1 погашен, таймер остановлен
- **LED2** (пин D4) мигает независимо с периодом `settings.led2Interval`
  (0 = выключен).
- **Heartbeat** раз в 10 секунд печатает в UART строку с uptime,
  счётчиками, режимом, периодом LED2 и статусом dirty-флага.
- **Все настройки** сохраняются в EEPROM и переживают перезагрузку.

## Распиновка (ACE-UNO)

| Пин      | Назначение              | Комментарий                          |
|----------|-------------------------|--------------------------------------|
| D22      | `LED_BUILTIN`           | Встроенный светодиод (LED1)          |
| D23      | `BTN_BUILTIN`           | Встроенная кнопка (активна по HIGH)  |
| D4       | LED2                    | Внешний светодиод через резистор 220–470 Ом |
| GND      | Земля                   | Общая для LED2                       |

### Подключение LED2

```text
D4 ────[ 220 Ω ]────▶|──── GND
LED
(анод к резистору)
```

Если LED не загорается — проверь полярность: длинная нога (анод) — к пину,
короткая (катод) — к GND.

### Питание

- **USB Type-C** — 5 В, для прошивки и отладки.
- **VIN** — 7–12 В, если нужна автономная работа.
- Драйвер USB-последовательного порта: **CH343P**.

## Жесты кнопки

| Жест             | Время       | Действие                                        |
|------------------|-------------|-------------------------------------------------|
| Короткое нажатие | < 2 с       | Смена режима по кругу: `SLOW → FAST → OFF →`   |
| Длинное          | 2…5 с       | `resetMode()` — вернуть `mode = SLOW` без сброса настроек |
| Сверхдлинное     | ≥ 5 с       | `factoryReset()` — все настройки к дефолтам     |

Каскад: при сверхдлинном удержании сначала сработает `resetMode`
(на 2-й секунде), а затем `factoryReset` (на 5-й секунде).
Это by design — пользователь может «передумать» и отпустить кнопку
между 2 и 5 секундами.

## Команды Console

Подключись к плате через USB-UART (9600 бод), открой монитор порта.
После загрузки увидишь приглашение `> `.

| Команда                    | Описание                                            |
|----------------------------|-----------------------------------------------------|
| `help`                     | Список команд                                        |
| `show`                     | Показать текущие настройки                          |
| `mode <slow\|fast\|off>`   | Сменить режим работы LED1                            |
| `set slow <ms>`            | Период SLOW (50..60000 мс)                          |
| `set fast <ms>`            | Период FAST (50..60000 мс)                          |
| `set count <n>`            | Тиков в серии LED1 (1..255)                         |
| `set longpress <ms>`       | Порог длинного нажатия (200..10000 мс)              |
| `led2 <ms>`                | Период LED2 (0 = off, 50..60000 мс)                 |
| `stats`                    | Uptime, счётчики, размер структуры Settings         |
| `clearstats`               | Обнулить `bootCount` и `buttonCount`                |
| `save`                     | Записать настройки в EEPROM                         |
| `reset`                    | Factory reset (все настройки к дефолтам)            |
| `dump`                     | Hex-дамп первых 32 байт EEPROM + field map          |
| `peek <addr>`              | Прочитать байт EEPROM по адресу (0..1023)           |
| `poke <addr> <val>`        | Записать байт в EEPROM                              |

Консоль **не блокирует** `loop()` — она читает только то, что уже
пришло в UART-буфер. Работает как event-driven парсер команд.

## ⚙️ Настройки в EEPROM

Структура `Settings` объявлена с `__attribute__((packed))` — без
выравнивающих паддингов. Занимает ровно 24 байта.

| Смещение | Размер | Поле            | Дефолт   |
|----------|--------|-----------------|----------|
| 0x00     | 1      | `mode`          | 0 (SLOW) |
| 0x01     | 4      | `intervalSlow`  | 1000     |
| 0x05     | 4      | `intervalFast`  | 250      |
| 0x09     | 2      | `blinkCount`    | 10       |
| 0x0B     | 2      | `longPressMs`   | 2000     |
| 0x0D     | 1      | `version`       | 3        |
| 0x0E     | 4      | `bootCount`     | 0        |
| 0x12     | 4      | `buttonCount`   | 0        |
| 0x16     | 2      | `led2Interval`  | 0        |
| **0x18** | **0**  | **конец**       |          |

### Версионирование

`settingsLoad()` проверяет `version`. Если значение не совпадает
с `SETTINGS_VERSION` — все настройки заменяются на `DEFAULTS`, и в лог
печатается `[EEPROM] Invalid version, using defaults`.
Это защита от чтения старой структуры после обновления прошивки.

### Грязный флаг (dirty)

Чтобы не изнашивать EEPROM частыми записями, применён паттерн
«черновик + чистовик»:

- `settingsIncButtonCount()` увеличивает счётчик **в RAM**
  и ставит `dirty = true`.
- Раз в минуту `saveTimer` вызывает `settingsFlushIfDirty()` —
  пишет EEPROM только если есть несохранённые изменения.
- Любая явная команда (`set`, `mode`, `save`, `reset`) сохраняет
  мгновенно и сбрасывает флаг.

Результат: 100 нажатий кнопки = 1 запись EEPROM вместо 100.
Потеря при внезапном отключении — до минуты нажатий.

## Сборка и прошивка

1. Установить **Arduino IDE**.
2. Установить пакет **Elron → MIK32 Амур** через Boards Manager.
3. Установить драйвер **CH343P** для USB-UART.
4. Открыть `Elron_8mb_2_leds.ino`.
5. Выбрать плату **ELBEAR ACE-UNO** (или ACE-NANO).
6. `Upload`.
7. Открыть монитор порта на **9600 бод**.

## 🧩 Что использовано из MIK32

- GPIO (LED1, LED2, кнопка)
- UART0 (Serial, 9600 бод)
- EEPROM (1024 байта пользовательских данных)
- `millis()` — источник времени для всех таймеров
- `__attribute__((packed))` — плотная упаковка структуры
