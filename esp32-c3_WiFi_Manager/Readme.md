# ESP32 WiFi Manager Core

Набор классов для управления Wi‑Fi на ESP32 (Arduino IDE) с упором на расширяемость и переиспользование в других проектах.

## Цель проекта

Создать модульное ядро для Wi‑Fi‑функционала (сканирование, подключение, хранение учётных данных) и отделить его от UI. Архитектура спроектирована так, чтобы классы можно было выносить в отдельную библиотеку и подключать к разным проектам (Serial‑меню, веб‑интерфейс, дисплей и т.п.).

---

## Основные классы

### `WiFiManager`
**Назначение:** низкоуровневое взаимодействие с модулем WiFi (сканирование сетей, подключение).  
**Что делает:**
- сканирует сети и заполняет массив `NetworkInfo`;
- подключается к сети с таймаутом;
- возвращает читаемые названия типов шифрования.
**Особенности:**
- не хранит состояние между вызовами;
- полностью абстрагирован от хранения данных и UI;
- использует фиксированные буферы для SSID/BSSID (без `String` в горячих путях).
**Для переиспользования:** можно подключать к любому проекту ESP32; единственная зависимость — `<WiFi.h>`.

---

### `WiFiCredentials`
**Назначение:** хранение и управление учётными данными Wi‑Fi (SSID + пароль).  
**Что делает:**
- сохраняет/загружает данные через `Preferences` в формате JSON;
- поддерживает миграцию из старого текстового формата;
- предоставляет методы для поиска, добавления, удаления и просмотра сохранённых сетей.
**Особенности:**
- логика миграции вынесена внутрь, но выполняется только при обнаружении старого формата;
- все операции с данными проходят через парсинг/сериализацию JSON;
- методы возвращают простые статусы (bool/int), вывод сообщений остаётся на стороне вызывающего кода.
**Для переиспользования:** класс можно вынести в библиотеку; при смене хранилища (например, на LittleFS) потребуется заменить только внутренние методы `loadData`/`saveData`.

---

### `AppState`
**Назначение:** машина состояний приложения и координация логики Wi‑Fi.  
**Что делает:**
- управляет текущим состоянием (`IDLE`, `SCANNING`, `CONNECTING`, `CONNECTED` и т.д.);
- запускает автоподключение при старте;
- координирует сканирование, подключение и сохранение текущей сети;
- предоставляет статус подключения и отладочную строку состояния.
**Особенности:**
- состояние и результаты сканирования хранятся внутри класса;
- публичные методы не зависят от UI и не выполняют вывод в Serial;
- блокировка ввода в `loop()` реализуется на уровне UI (например, в `Menu`).
**Для переиспользования:** ядро логики; можно подключать к разным интерфейсам (Serial, веб, дисплей).

---

### `Menu`
**Назначение:** консольный интерфейс на Serial для управления Wi‑Fi и просмотра состояния.  
**Что делает:**
- отображает меню и обрабатывает ввод пользователя;
- запрашивает подтверждения и валидирует ввод (числа, непустые строки);
- вызывает методы `AppState` для выполнения действий;
- красиво выводит таблицу найденных сетей с динамической шириной колонок.
**Особенности:**
- жёстко привязан к `Serial` (ввод/вывод);
- содержит UX‑логику (таймауты, подсказки, подтверждения);
- не является частью «ядра» для переиспользования в других UI.
**Для переиспользования:** этот класс остаётся в конкретном проекте; для другого UI (веб, дисплей) создаётся новый класс интерфейса.

## Ограничения и допущения

- **Однопоточность:** все классы спроектированы для вызова из `loop()` без параллельных задач. При использовании FreeRTOS или прерываний требуется дополнительная синхронизация.
- **Блокирующие операции:** подключение к Wi‑Fi и ожидание ввода пользователя блокируют выполнение. Это допустимо для прототипа; для неблокирующего дизайна потребуется рефакторинг этих участков.
- **Максимальный размер данных:**
  - макс. количество сканируемых сетей: `MAX_NETWORKS = 50`;
  - длина SSID ограничена размером буфера в `NetworkInfo`.
- **Порядок ключей в JSON:** не гарантируется; для работы с сохранёнными сетями рекомендуется использовать поиск по SSID, а не по индексу.

## Планы по развитию

- вынести классы `WiFiManager`, `WiFiCredentials`, `AppState` в отдельную библиотеку;
- реализовать неблокирующую версию сканирования и подключения;
- добавить абстракцию над хранилищем (интерфейс для замены Preferences на LittleFS и др.);
- создать пример с веб‑интерфейсом, использующим то же ядро `AppState`.
